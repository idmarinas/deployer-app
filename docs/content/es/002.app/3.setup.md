Cuando arrancas :vars{n="project"} por primera vez, la aplicación realiza un **diagnóstico automático** y te redirige a la pantalla necesaria para dejar la base de datos lista.

## Diagnóstico al arrancar

Al iniciar, el frontend comprueba de forma no bloqueante:

1. El **estado del vault de Stronghold** (archivo, snapshot y client `encrypt-keys`).
2. Si **existe la base de datos** (`check_database_exists`).
3. Si hay **migraciones pendientes** (`has_migrations_pending`).

Según el resultado:

| Situación | Redirección |
| --- | --- |
| No existe la base de datos | `/deployer` — asistente de configuración inicial |
| Existe, pero hay migraciones pendientes | `/deployer/migrations` — ejecutar migraciones |
| Existe y está al día | `/dashboard` — uso normal de la app |

## Asistente de configuración

La pantalla de configuración (`/deployer`) muestra una guía de pasos con el orden del proceso. Desde ahí puedes:

- **Seleccionar archivo SQLite** — elegir un archivo `.sqlite` existente. La aplicación lo valida, ejecuta las migraciones pendientes si las hay, guarda la ruta y completa el seed inicial.
- **Crear nuevo archivo SQLite** — crear un archivo nuevo (nombre sugerido `deployer-app.sqlite`), inicializar la base de datos, ejecutar migraciones, validar el resultado, guardar la ruta y completar el seed inicial.
- **Reiniciar configuración** — reintentar el proceso si alguna fase falla.

## Seed inicial

Al completar la configuración inicial, la aplicación ejecuta un seed de datos:

- **Ajustes iniciales** — al crear una base de datos nueva se guardan `locale` y `theme_color` en la tabla `settings`.
- :labels-version{version="0.2" is-new size="sm"} **Comandos internos** — se insertan o actualizan los comandos internos sin duplicarlos, tanto al crear una base de datos como al cargar una existente o ejecutar migraciones pendientes.

## Migraciones pendientes

Si la base de datos existe pero le faltan migraciones, la app te lleva a `/deployer/migrations`. Desde esa pantalla puedes ejecutar las migraciones, validar la base de datos y completar el seed inicial; si una fase falla, puedes reiniciar el proceso.

Una vez completadas, la app continúa al `/dashboard`.
