Esta sección explica cómo funciona **:vars{n="project"}** por dentro: sus componentes, cómo se guardan y protegen los datos y cómo fluye la información entre el frontend y el backend. También describe el [borrado lógico y la papelera](./trash), común a todos los módulos.

## Arquitectura

:vars{n="project"} es una **aplicación de escritorio dividida en dos mitades** que trabajan juntas:

- **Frontend (Vue 3 + TypeScript + Nuxt UI v4)** — toda la interfaz de usuario. Nuxt UI se usa **como librería**, no como meta-framework: la aplicación se construye con Vite y no hay servidor adicional.
- **Backend (Rust + Tauri 2)** — los procesos nativos que la interfaz no puede hacer por sí sola: conexiones SSH/SFTP, gestión del vault de Stronghold, inicialización de la base de datos y ejecución de migraciones.

Conjunto de piezas:

- **Base de datos local (SQLite)** — todos los datos se guardan en un archivo SQLite en tu equipo; nunca salen de tu máquina.
- **Acceso a datos (Drizzle ORM en modo proxy)** — el frontend lee y escribe la base de datos a través de Drizzle. El proxy se encarga de **cifrar y descifrar de forma transparente** los campos sensibles declarados como `encryptedText(...)`.
- **Vault Stronghold** — guarda las claves AES con las que se cifran las credenciales. El frontend es el **único escritor** del vault; el backend solo lo abre para **leer** cuando necesita descifrar credenciales SSH.
- **Orquestación SSH/SFTP** — el backend establece las conexiones SSH/SFTP y ejecuta comandos remotos, pruebas de conexión, consola, transferencia de archivos y cancelación de tareas. Algunas funciones, como métricas, información del sistema o actualizaciones, se ejecutan como comandos guardados sobre esa conexión.

```text
│  · cifra/descifra   │  ◄───  │  · Stronghold (lect.)│

└─────────────────────┘        └─────────────────────┘
        │  Drizzle proxy                │
        ▼                              ▼
   ┌────────────────────────────────────────┐

   └────────────────────────────────────────┘
```
