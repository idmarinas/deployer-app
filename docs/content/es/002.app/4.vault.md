**:vars{n="project"}** guarda los datos sensibles **cifrados** en la base de datos local. Esta página describe el mecanismo técnico; la política de reporte está en [Seguridad](/security) y la gestión de claves desde la interfaz en [Configuración → Seguridad](/configuration/security).

## Qué se cifra

Se cifran los campos declarados como `encryptedText(...)` en el esquema de Drizzle:

| Campo | Tabla | Condición |
| --- | --- | --- |
| `password` | `deployer_hosts` | Siempre |
| `key_content` | `deployer_passkeys` | Siempre |
| `passphrase` | `deployer_passkeys` | Siempre |
| `value` | `deployer_variables` | Solo cuando la variable es secreta |

## Cómo se cifra

- El algoritmo es **AES-256-GCM** con un **nonce aleatorio de 12 bytes** por operación.
- Los valores cifrados se guardan en la base de datos con el formato: **`ENC:{version}:<base64>`** (`nonce` + `ciphertext`).
- El vault (`vault.hold`) y el *salt* de 32 bytes se guardan en el directorio local de la aplicación.

## Claves versionadas

Cada campo tiene su propia clave, versionada por scope:

```text
encrypt:{tabla}.{columna}:{version}
```

Esto permite **rotar** una clave sin perder datos: al rotar se conservan las versiones anteriores y los valores antiguos se pueden **re-cifrar** con la versión actual. La rotación y el re-cifrado se gestionan desde [Configuración → Seguridad](/configuration/security).

## Quién escribe y quién lee

- El **frontend es el único escritor** del vault: cifra al guardar, descifra o **enmascara** al leer.
- El **backend de Rust abre el vault solo en modo lectura** (`StrongholdVault::open`) para descifrar las credenciales cuando establece una conexión SSH/SFTP.
- Al leer, el proxy de Drizzle reemplaza los valores cifrados por `BLANK_VALUE` para que la interfaz **nunca** reciba el contenido cifrado en bruto, salvo cuando se pide descifrado explícito.

## Contraseña del vault y keychain

- La contraseña del vault se **genera aleatoriamente** (64 caracteres hexadecimales) en la primera ejecución.
- Se guarda en el **keychain del sistema operativo** mediante el crate `keyring`.
- La clave del vault se deriva con **Argon2** a partir de esa contraseña y del *salt*.

## Diagnóstico del vault

:labels-version{version="0.1.1" is-new size="sm"} Al arrancar, la aplicación comprueba de forma no bloqueante el estado del vault: si el archivo existe, si el snapshot carga, si el client `encrypt-keys` está presente y si faltan claves.

::note
Aunque alguien acceda al archivo de la base de datos, no puede leer las credenciales ni los secretos sin la clave del vault, que reside en el keychain del sistema.
::
