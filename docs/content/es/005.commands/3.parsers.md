El **parser de salida** de un comando determina cómo se procesa su salida. Está definido en el campo **Parser de salida** del comando, con un selector de cuatro opciones y campos concretos según el tipo.

## Tipos de parser

- **raw** — la salida no se procesa: se muestra tal cual. Útil para comandos cuya salida lee una persona (logs, status con formato).
- **json** — la salida se interpreta como **JSON** y se estructura. Ideal para comandos que devuelven datos (p. ej. `uptime`, scripts con `--json`).
- **line-based** — la salida se procesa **línea a línea** y se convierte en un objeto `clave → valor` (las claves repetidas se agrupan en un array), con transformaciones `string`, `number` o `boolean` para listados y tablas de texto.
- **regex** — la salida se analiza con una **expresión regular** sobre todo el texto crudo, con `flags` y grupos de captura, para extraer campos concretos.

## Configuración del parser

El parser se guarda como un objeto con la configuración del tipo elegido. El formulario ofrece un selector con cuatro opciones y, según el tipo, campos estructurados: reglas `match`/`key`/`transform` para `line-based`, y patrón, `flags` y grupos para `regex`. No hay un editor JSON libre.

## Dónde se usa

La salida procesada es la base para que los [comandos internos](./built-in) presenten los datos de un host (info, métricas y actualizaciones) de forma estructurada. El [diálogo de test de comandos](./testing) muestra únicamente la salida cruda y el código de salida, sin aplicar el parser.
