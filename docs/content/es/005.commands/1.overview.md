Los **comandos** son tareas de SSH **reutilizables** que puedes ejecutar contra cualquier servidor sin volver a escribirlas.

## Qué guarda un comando

- **Nombre** — identificador legible.
- **Clave** — identificador único en formato slug (minúsculas, números y guiones bajos entre grupos alfanuméricos; sin guiones; de 3 a 120 caracteres, o 3 a 64 al editar). Se **autogenera** a partir del nombre, pero puedes adaptarla en el alta; en edición el campo es de solo lectura. La inmutabilidad la impone la interfaz, no el esquema.
- **Descripción** — texto enriquecido opcional.
- **Comando** — el script o comando a ejecutar por SSH (en formato monoespaciado).
- **Parser de salida** — cómo interpretar la salida del comando ([Parsers](./parsers)).
- **Timeout** — tiempo máximo de ejecución (1-3600 segundos). El formulario de alta y la base de datos parten de **30**; el esquema y el fallback del runner usan **300**.
- **Parámetros de entrada** — definición de los valores que se piden al ejecutar y se interpolan con `{{params.<clave>}}`; el valor no se guarda ([Parámetros de entrada](./inputs)).

## Para qué sirven

- **Automatizar** — tareas repetidas (estado del sistema, logs, reinicios, comprobaciones de salud...).
- **Probar** — contra un host real antes de usarlo ([Testing](./testing)).
- **Reutilizar** — la misma definición en cualquier servidor habilitado.

## Comandos internos

La aplicación incluye comandos **internos de semilla** que usa la propia interfaz para las [vistas de host](/hosts/overview) ([Comandos internos](./built-in)).

## Habilitado

El conmutador **habilitado** activa o desactiva el comando; los deshabilitados no se pueden ejecutar contra un servidor, aparecen en la pestaña **Inactivos** y conservan la acción **Probar**, que falla con un error de comando deshabilitado ([Gestionar comandos](./manage)).
