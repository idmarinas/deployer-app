Un **parámetro de entrada** es un valor que el comando pide antes de ejecutarse y que se sustituye en el script mediante la expresión `{{params.<clave>}}`.

A diferencia de las [variables globales](/variables/overview), el parámetro se declara en el propio comando y su valor **no se guarda**: vive solo durante esa ejecución. La plantilla almacenada no cambia.

## Tipos disponibles

- **text** — cadena libre. También sirve para pasar una lista separada por espacios (ver [Listas](#listas)).
- **number** — número finito. Un campo vacío **no** se convierte en `0`: la ejecución se bloquea si el parámetro es obligatorio y, si no lo es, se interpola como cadena vacía.
- **boolean** — interruptor. Si no se toca, se envía `false`, salvo que tenga un valor por defecto `true`.
- **select** — una de las opciones declaradas. El valor puede ser texto o número.

No existe un tipo `list` ni un tipo de texto largo; para eso se usa `text` con la convención de listas. Tampoco hay parámetros secretos: los secretos siguen siendo [variables globales](/variables/overview).

## Definir parámetros

En el formulario del comando, la sección **Parámetros de entrada** (entre el timeout y el script) permite añadir, editar, reordenar y eliminar parámetros. Cada uno declara:

- **Clave** — slug usado en el script: minúsculas, números y guiones bajos, empezando por letra.
- **Etiqueta** — texto visible en el diálogo de ejecución.
- **Tipo** — uno de los cuatro anteriores.
- **Obligatorio** — impide ejecutar sin un valor.
- **Valor por defecto** — literal o variable global (ver [Valores por defecto](#valores-por-defecto)).
- **Ayuda** — texto opcional junto al campo.
- **Opciones** — solo para `select`; al menos una, con `value` único y no vacío.

Un comando admite hasta **20** parámetros. Al guardar se rechazan las claves repetidas o mal formadas, las etiquetas vacías, un `select` sin opciones o con valores vacíos o repetidos, y un valor por defecto que no encaje con el tipo.

## Referenciar en el script

La clave se escribe como `{{params.clave}}`:

```bash
if [ -d "{{params.remote_dir}}" ]; then
  ls -la "{{params.remote_dir}}"
fi
```

Mientras se escribe, `{{` abre los ámbitos disponibles (`global` y, si hay parámetros declarados, `params`) y `{{params.` lista las claves declaradas. El linter marca las referencias a claves que no existen, pero **no impide guardar**; el [diálogo de prueba](./testing) sí bloquea la ejecución hasta corregirlas.

## Valores por defecto

Un valor por defecto puede ser un literal (`/var/www`, `22`, `true`) o una expresión que combine texto y una o varias referencias `{{global.slug}}`. Se resuelve al abrir el diálogo y otra vez en el runner para ejecutar; antes de eso hay previsualización en el editor y validación al guardar.

Reglas:

- Solo se admiten variables de la raíz `global`, y deben existir, estar **habilitadas** y **no ser secretas**. Si no, el diálogo muestra el problema y no permite ejecutar.
- No hay dependencias entre parámetros: un valor por defecto no puede referenciar `{{params.*}}`.
- Un `boolean` solo admite un literal booleano.
- El valor resuelto se coacciona al tipo: un `number` debe ser numérico y un `select` debe coincidir con una de sus opciones.
- `obligatorio` se evalúa después de aplicar los valores por defecto, y `0` y `false` cuentan como valor presente.
- Si borras un campo que tenía valor por defecto, se envía vacío: el valor por defecto **no se vuelve a aplicar** durante esa ejecución.

## Listas

Una lista se pasa como **una cadena con los elementos separados por espacios**. El motor interpola el texto tal cual y el shell remoto aplica el *word splitting*.

```bash
# Sin comillas alrededor de la expresión de la lista en el comando; sí en la comprobación de vacío.
if [ -n "{{params.packages}}" ]; then
  sudo DEBIAN_FRONTEND=noninteractive apt-get install --only-upgrade -y {{params.packages}}
fi
```

- **No entrecomilles** la expresión de una lista: con comillas, todos los elementos llegarían como un único argumento.
- Sí se entrecomilla cuando solo se comprueba si está vacía (`[ -n "…" ]`).
- El motor no separa ni valida elementos; si el valor procede de una selección dinámica, valida los elementos antes de unirlos con espacios.

## Entrecomillado y seguridad

La sustitución es **literal**, igual que en las variables globales. El autor del comando decide las comillas según el uso: entrecomilla un valor único (`"{{params.path}}"`) y no entrecomilles una lista.

::warning
El valor no se escapa ni se sanea. Todo lo que escriba el usuario se inserta en el script; entrecomillar correctamente es responsabilidad de quien define el comando.
::

Los valores de los parámetros no se guardan en la base de datos, no se reutilizan entre ejecuciones y no se comparten entre servidores. Para datos sensibles, usa variables globales secretas en lugar de parámetros.

## Límites

- Máximo **20** parámetros por comando.
- Tipos disponibles: `text`, `number`, `boolean` y `select`.
- Sin entrada de ficheros, sin listas nativas y sin parámetros secretos.
- Los valores no se persisten; cada ejecución empieza con los valores por defecto declarados.

Para saber cómo se combinan los parámetros con el resto de la plantilla, consulta [Interpolación de variables](/variables/interpolation) y [Parsers](./parsers).
