El **diálogo de test** permite ejecutar un comando contra un servidor real y ver su salida antes de guardarlo o de usarlo de forma definitiva.

## Cómo funciona

1. Selecciona un **servidor** (solo se muestran los hosts habilitados).
2. Si el comando declara [parámetros de entrada](./inputs), rellénalos en el bloque **Parámetros de entrada**: los valores por defecto se resuelven al abrir el diálogo y **cualquier problema** (obligatorio vacío, default no resoluble o valor inválido) bloquea **Ejecutar** con el aviso **Revisa los parámetros**. También se deshabilita si no hay servidor seleccionado o faltan variables globales.
3. La vista previa tiene dos pestañas: **Interpolada** (por defecto) muestra el comando con parámetros y variables resueltos y las secretas enmascaradas como `••••••`; **Original** muestra la plantilla sin resolver. El envío real resuelve las secretas sin enmascarar. Si hay errores de interpolación o de parámetros, la ejecución queda bloqueada.
4. Durante la ejecución no hay salida incremental. Al terminar correctamente se muestra la salida completa junto a **Código de salida: 0**; si el comando acaba con un código > 0, se muestra el mensaje de error con la salida redactada y no aparece la insignia de código.

## Dónde está disponible

- **Botón Probar del toolbar** en el formulario de alta — ejecuta el comando que estás definiendo, aún sin guardar.
- **Botón Probar en el formulario de edición** y **acción «Probar»** en la tabla — ejecutan la definición guardada, incluidos sus parámetros. En la pestaña **Inactivos** la prueba falla porque el comando está deshabilitado.

## Diferencias según el origen

- **Comando guardado** — usa la definición guardada del comando.
- **Comando ad-hoc** — el texto y los parámetros del formulario, aún sin guardar.

::note
En edición, la vista previa usa el script y la definición de parámetros del formulario; la ejecución usa el script, el parser, el timeout y la definición guardados, aunque con los valores rellenados en el diálogo. Guarda antes de probar si cambiaste el script o la definición de parámetros.
::

::note
El test utiliza las **credenciales del servidor seleccionado** y verifica su **huella SSH**, así que es una forma segura de comprobar que el comando funciona contra un host concreto antes de automatizarlo.
::
