Una variable se usa escribiendo `{{global.slug}}`, donde `slug` es el de la variable. La **plantilla guardada no se modifica**: la sustitución ocurre en tiempo de ejecución.

## Sintaxis

Las referencias admiten `global` para las variables y `params` para los parámetros declarados en el comando; no se permiten espacios dentro de las llaves:

```text
{{global.deploy_path}}     # válido
{{params.remote_dir}}      # válido en un comando con ese parámetro
{{ global.deploy_path }}   # no válido (espacios)
{{global.deploy_path }}    # no válido (espacio final)
```

::note
`params` está disponible desde 0.4.0; `global` desde 0.3.0.
::

Los slugs declarados se validan en minúsculas, números y guiones bajos. Si escribes mayúsculas en la referencia, el analizador la interpreta y falla como variable inexistente; los guiones quedan como texto literal.

Para escribir la apertura de forma literal, escápala con una barra invertida:

```text
\{{global.deploy_path}}   # se envía como {{global.deploy_path}}
```

::note
La aplicación solo suministra `global` y, en comandos con [parámetros de entrada](/commands/inputs) declarados, `params`. Una referencia como `{{vars.x}}` produce un error de ámbito no disponible y **bloquea la ejecución**; no queda como texto literal. En cambio, formatos ajenos como `{{.Names}}`, `{{end}}`, `{NAME}` o `${NAME}` se dejan intactos.
::

## Dónde se aplica

- En el **comando** de los comandos guardados.
- En el **comando** y el **directorio de trabajo** de la consola manual, que interpola las referencias pero no ofrece linter, autocompletado ni vista previa.

El linter del formulario de comandos avisa de las referencias inexistentes o deshabilitadas, pero **no impide guardar**. El diálogo de prueba, en cambio, **bloquea la ejecución** mientras haya errores.

## Autocompletado y resaltado

En el editor, `{{` abre la lista de ámbitos (`global` y, si el comando declara parámetros con clave, `params`) y las entradas aparecen al escribir una letra. El filtrado funciona tanto por slug como por nombre:

```text
{{             # ámbitos disponibles (global, params)
{{g            # global y sus variables
{{global.      # todas las variables globales
{{global.de    # global.deploy_path
{{de           # global.deploy_path (coincide por slug)
{{params.      # claves de los parámetros declarados
```

Cada variable muestra el **nombre** y, debajo, la expresión junto a una vista previa de su valor (`global.deploy_path [/var/www]`). Los valores largos se recortan con `…`; en las secretas aparece `••••••` y la opción lleva un icono de candado. Al aceptar una secreta solo se inserta `{{global.slug}}`, **nunca su valor**. Los parámetros muestran su etiqueta y el tipo declarado.

Las referencias se resaltan en color primario y las secretas en ámbar. El resaltado es informativo; el linter sí emite una advertencia para las secretas, que aparece en el diálogo de prueba, aunque no impide guardar.

## Vista previa del diálogo de prueba

Cuando hay referencias resolubles y la plantilla no tiene errores, el diálogo **Probar comando** muestra dos pestañas:

- **Interpolada** (por defecto): vista previa del comando con las variables resueltas y las secretas enmascaradas como `••••••`, usando los valores provisionales de los parámetros. El envío real resuelve los secretos sin enmascararlos.
- **Original**: la plantilla del comando, sin resolver.

En ambas vistas las expresiones aparecen resaltadas. El aviso bajo la vista previa aparece solo si hay secretas y se refiere a ellas: se resuelven al ejecutar el comando. Si la plantilla tiene errores, no se puede calcular la vista interpolada, las pestañas se ocultan y la ejecución queda bloqueada.

## Resolución

- Solo se resuelven variables **habilitadas**.
- Una referencia inexistente o deshabilitada **bloquea la ejecución**.
- Las variables secretas se descifran solo al ejecutar; en el formulario, la vista previa y los logs aparecen enmascaradas (`••••••`). Los mensajes de error también se redactan.
- No hay recursión: el valor de una variable no vuelve a interpolarse.
