Una variable se usa escribiendo `{{global.slug}}`, donde `slug` es el de la variable. La **plantilla guardada no se modifica**: la sustitución ocurre en tiempo de ejecución.

## Sintaxis

La raíz `global` es obligatoria y no se permiten espacios dentro de las llaves:

```text
{{global.deploy_path}}     # válido
{{ global.deploy_path }}   # no válido (espacios)
{{global.deploy_path }}    # no válido (espacio final)
```

El slug usa minúsculas, números y guiones bajos; no admite mayúsculas ni guiones.

Para escribir la apertura de forma literal, escápala con una barra invertida:

```text
\{{global.deploy_path}}   # se envía como {{global.deploy_path}}
```

::note
El analizador reconoce otras raíces, pero la aplicación solo suministra `global`. Una referencia como `{{vars.x}}` produce un error de ámbito no disponible y **bloquea la ejecución**; no queda como texto literal. En cambio, formatos ajenos como `{{.Names}}`, `{{end}}`, `{NAME}` o `${NAME}` se dejan intactos.
::

## Dónde se aplica

- En el **comando** y el **directorio de trabajo** de los comandos guardados.
- En la **consola manual**, que interpola las referencias pero no ofrece linter, autocompletado ni vista previa.

El linter del formulario de comandos avisa de las referencias inexistentes o deshabilitadas, pero **no impide guardar**. El diálogo de prueba, en cambio, **bloquea la ejecución** mientras haya errores.

## Autocompletado y resaltado

En el editor, `{{` abre la lista de ámbitos —hoy solo `global`— y las variables aparecen al escribir una letra. El filtrado funciona tanto por slug como por nombre:

```text
{{             # ámbitos disponibles (global)
{{g            # global y sus variables
{{global.      # todas las variables globales
{{global.de    # global.deploy_path
{{de           # global.deploy_path (coincide por slug)
```

Cada opción muestra el **nombre** y, debajo, la expresión junto a una vista previa de su valor (`global.deploy_path [/var/www]`). Los valores largos se recortan con `…`; en las secretas aparece `••••••` y la opción lleva un icono de candado. Al aceptar una secreta solo se inserta `{{global.slug}}`, **nunca su valor**.

Las referencias se resaltan en color primario y las secretas en ámbar. Es un resaltado informativo: una variable secreta **no** es un error ni una advertencia.

## Vista previa del diálogo de prueba

Cuando el comando tiene referencias, el diálogo **Probar comando** muestra dos pestañas:

- **Interpolada** (por defecto): el comando tal como se enviará al servidor, con las variables resueltas y las secretas enmascaradas como `••••••`.
- **Original**: la plantilla guardada, sin resolver.

En ambas vistas las expresiones aparecen resaltadas y bajo la vista previa un aviso recuerda que esas variables se resuelven solo al ejecutar el comando. Si la plantilla tiene errores, no se puede calcular la vista interpolada y la ejecución queda bloqueada.

## Resolución

- Solo se resuelven variables **habilitadas**.
- Una referencia inexistente o deshabilitada **bloquea la ejecución**.
- Las variables secretas se descifran solo al ejecutar; en el formulario, la vista previa y los logs aparecen enmascaradas (`••••••`). Los mensajes de error también se redactan.
- No hay recursión: el valor de una variable no vuelve a interpolarse.
