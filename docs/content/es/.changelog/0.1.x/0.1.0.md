## Destacados de la versión

- Configuración inicial: guía de pasos de configuración de la app con dos botones para seleccionar un archivo de base de datos SQLite existente o crear uno nuevo, ejecutando las migraciones.
- Gestión de hosts: CRUD completo con test de conexión SSH, comprobación de sistema/métricas y actualizaciones de paquetes.
- Gestión de passkeys: CRUD con generación de claves SSH (RSA, ED25519, ECDSA), derivación de fingerprint y exportación a servidores.
- Consola remota: ejecución de comandos SSH con streaming en tiempo real, subida/bajada de archivos y cancelación.
- Cifrado AES-GCM con vault de Stronghold para campos sensibles (passwords, key_content, passphrase).

## Seguridad

- Sistema de cifrado/descifrado transparente con AES-GCM para campos declarados como `encryptedText(...)` en el esquema de Drizzle, cubriendo `hosts.password`, `passkeys.key_content` y `passkeys.passphrase`. ([`c5ea7f3`](https://github.com/idmarinas/deployer-app/commit/c5ea7f3)) ([@idmarinas](https://github.com/idmarinas))
- Vault de Stronghold con claves versionadas por scope (`encrypt:{tabla}.{col}:{version}`), rotación de claves y re-encriptación de datos desde la pestaña de seguridad. ([@idmarinas](https://github.com/idmarinas))
- El cifrado y descifrado se lleva a cabo en el frontend, que es el único escritor del vault de Stronghold; el backend solo lee claves en modo solo lectura (`StrongholdVault::open`) para descifrar credenciales SSH. ([`9f68631`](https://github.com/idmarinas/deployer-app/commit/9f68631)) ([@idmarinas](https://github.com/idmarinas))
- Enmascarado de todos los valores cifrados con `BLANK_VALUE` en las respuestas del proxy para que el frontend nunca reciba datos cifrados en bruto. ([`91a349c`](https://github.com/idmarinas/deployer-app/commit/91a349c)) ([@idmarinas](https://github.com/idmarinas))
