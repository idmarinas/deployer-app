## Destacados de la versión

- Vault de Stronghold: se corrige el error por el que el backend no podía descifrar los valores encriptados (hosts.password, passkeys.key_content, passkeys.passphrase) al no cargar el client `encrypt-keys` desde el snapshot.
- Nuevo comando `check_vault_health` para diagnosticar el estado del vault (archivo, snapshot, client y claves faltantes) desde la app.

## Añadido

- Comando de backend `check_vault_health` y función `checkVaultHealth()` en el frontend para diagnosticar el estado del vault de Stronghold, informando si el archivo existe, si el snapshot carga, si el client `encrypt-keys` está presente y qué claves faltan. La comprobación se ejecuta de forma no bloqueante al arrancar la app. ([`8cee94c`](https://github.com/idmarinas/deployer-app/commit/8cee94c)) ([@idmarinas](https://github.com/idmarinas))

## Correcciones

- Se corrigió el error por el que el backend desencriptaba incorrectamente los valores cifrados: `StrongholdVault::open` no cargaba el client `encrypt-keys` desde el snapshot (`load_snapshot` no lo puebla en memoria), por lo que ahora se llama explícitamente a `load_client`. También se eliminó el intento de crear el client desde Rust, dejando el acceso estrictamente de solo lectura, y se añadieron mensajes de error claros cuando el vault, el client o la clave no existen. ([`8cee94c`](https://github.com/idmarinas/deployer-app/commit/8cee94c)) ([@idmarinas](https://github.com/idmarinas))
- Se incrementó la versión de la app a 0.1.1 en `package.json` y `tauri.conf.json`. ([`0181f2a`](https://github.com/idmarinas/deployer-app/commit/0181f2a)) ([@idmarinas](https://github.com/idmarinas))
