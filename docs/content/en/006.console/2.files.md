The remote console includes the **Upload file** and **Download file** tabs. Both work over SFTP on the selected host and share the same output terminal as [Running commands](./usage).

## Download while keeping the structure

Always set a **local destination**: the download does not start without it. The application creates the intermediate local directories; in **Directory** mode —and in **Auto** when it detects a directory— it reproduces the remote tree under the destination. In **File** mode it writes directly to the given path. The interface does not show base64 content; files are saved to disk.

The **download mode** determines how the remote path is interpreted:

- **Auto (based on remote type)** — detects whether it is a file or a directory and chooses the right treatment.
- **File** — downloads a single file to the given path.
- **Directory** — walks the remote tree; the destination picker selects a folder.

::warning
In **Directory** mode, the destination is the folder where the structure will be recreated, not the name of a file.
::

**Symbolic links** are followed as in an FTP client: if they point to a directory, their content is downloaded (for example, `current` → `releases/2025-…`), and if they point to a file, that file is downloaded. Broken links found during the walk are skipped with a warning in the terminal, while a broken link in the root path produces an error. To avoid cycles, the walk is limited to **32 levels** of depth: when the limit is reached, an error is emitted and the transfer is aborted.

## Control the existing destination

**Overwrite** is enabled by default. If you disable it, files that already exist at the destination are skipped and the warning appears in the terminal. Progress is shown **per file**, not byte by byte, and the saved path is added only for successful downloads; the final status —**Cancelled**, **Skipped** or code— appears in the terminal header.

## Upload files and directories

**Directory (recursive)** sends the whole local tree. The **chmod** field applies octal permissions only to uploaded files; if the host does not support them, a warning is recorded but the transfer continues.

Both tabs let you adjust **SSH retries**: the field starts at **3** and limits reconnection attempts; the backend also applies 3 when it receives `null`.

## Cancel a transfer

The **Cancel** button appears while the operation is in progress and acts on the active job. The transfer stops at the next safe point and the terminal shows the **Cancelled** status.
