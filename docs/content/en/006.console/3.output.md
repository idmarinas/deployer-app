The remote console terminal shows output with an almost black background and light green text, in a monospace font.

## Streaming output

Standard output and error output are interleaved **in the order the host produces them** and appear almost in real time, grouped in ~100 ms chunks; order is preserved within each job. This lets you follow the progress of long-running commands (deployments, logs, builds) without waiting for them to finish.

While the execution is in progress, the header shows **Running…**. Connection, timeout and cancellation errors are appended to the terminal text; for command runs no `finished` event is emitted, so no exit code appears. Transfers in 0.4.0 do have a final status: cancellation uses code `130` and errors use `1`, although the header shows **Cancelled** or the error instead of the badge.

## Exit code

The exit-code badge only appears once the execution has finished, a code has been received and the status is not `running`, `cancelled` or `skipped`:

- **`0`** — the command finished successfully (green badge).
- **Non-zero** — the command finished with an error (red badge); the value is decided by the remote process.

::note
Since 0.4.0 every operation has a job identifier: the `started` event exposes it and `finished` reports the status (`success`, `error`, `cancelled`), the code, the duration and a message. The **Cancelled** and **Skipped** statuses have their own badges in the header.
::

## Tips

- **Clear** removes the output, the error and the exit code; it is only available when there is output in the terminal. If there is only an error, the button does not appear, and pressing it does not cancel or clear a job in progress.
- **Cancel** interrupts the job and closes the SSH session, but does not send a signal to the remote process: it may keep running and no exit code is shown.
- Ad-hoc executions use the same component as the command test dialog (no page available yet in this locale), although there the full result is shown at the end, without streaming.
