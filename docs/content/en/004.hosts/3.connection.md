The **connection test** checks that the host responds over SSH with the configured credentials.

## Where it runs

- From the **host listing**, in the actions column of each row.
- From the host's **detail view**.
- Right after **saving a new host**, to obtain the server fingerprint.
- From **Check and confirm**, in the **Host fingerprint** field of the edit form.

## How it works

When you press the button, the app tries to establish an SSH session with the saved details. The result is shown with a notification:

- **Loading** — the test is in progress.
- **Success** — the connection was established correctly.
- **Error** — with the reason (incorrect credentials, unreachable host, closed port, changed server key, etc.).

## Notes

- The test **has no wait time**: after a check, you can test again whenever you want. The button only stays in a loading state while a test is in progress.
- It also works with **disabled hosts**: checking the connection is not restricted by the *enabled* toggle.
- Session establishment times out after **15 seconds** (`client::connect` timeout), when the error is notified. Once connected, remote execution allows **300 seconds**.

## Server fingerprint

The test also verifies the **SSH fingerprint** stored on the host (`SHA256:<base64>`):

- If the host has no fingerprint yet, the connection is rejected and the observed fingerprint is shown so you can confirm it from the form.
- If the server key changes, the connection is rejected with a mismatch notice; confirm the new fingerprint from the host edit form only if the change is legitimate.

::note
The connection test uses the host's current credentials: if you have just changed the password or key, the result reflects that configuration.
::
