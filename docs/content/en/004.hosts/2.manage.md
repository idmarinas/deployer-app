The **Hosts** module lets you manage all your hosts.

## Listing

The hosts table shows: number, name, IP, port, authentication type, whether it is enabled and its actions (view, edit, delete, **Test connection**). Each row can be expanded to see more details.

## Create a host

From the **Add host** button, define the **name** (and optional description), the **host** (IPv4 or IPv6), the **port** (0-65535; 22 by default) and the **username**. Choose the **authentication type**: **Password** (required field) or **Access key** (select an access key). Save.

The **Base directory (file manager)** field sets the initial path of the remote panel. It accepts absolute paths with `/`, `C:\...` or UNC; if left empty, the root `/` is used.

::note
This base directory is not the working directory of the remote console or of deployment commands: it only decides where browsing starts in the [file manager](/file-manager/navigation). You can change directory while browsing and **Reset path** goes back to this value.
::

The form **validates the uniqueness** of the name asynchronously against the database; the check does not filter `deleted_at`, so a name in the trash is still considered taken.

When saving, the app checks the connection right after creating the host and shows the server's **SSH fingerprint** for you to confirm. That fingerprint is associated with the host and verified on every connection; you can also obtain and confirm it from the edit form.

## View

The detail view shows the basic data (name, IP, port, username, authentication, base directory and SSH fingerprint) along with the enabled state. The rest of the information is organized into the tabs [System information](./system-info), [Updates](./updates) and [Metrics](./metrics).

## Edit

The edit form is the same as the creation form, preloaded. You can change any field, including the authentication method and the file manager base directory. If you switch from password to key (or vice versa), the field that no longer applies is cleared automatically. The **Host fingerprint** field is read-only: use **Check and confirm** to obtain it (if it does not exist yet) or to reconfirm a new fingerprint after a legitimate server key change.

## Enable / disable

The **Enabled** toggle activates or deactivates the host. Disabled hosts do not appear in the server selectors of the **console**, the **Test command** dialog or the **file manager**. Their saved listings are discarded and interrupted transfers cannot be retried while the host remains disabled.
