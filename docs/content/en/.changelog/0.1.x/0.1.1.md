## Release highlights

- Stronghold vault: fixed the error where the backend could not decrypt the encrypted values (`hosts.password`, `passkeys.key_content`, `passkeys.passphrase`) because the `encrypt-keys` client was not loaded from the snapshot.
- New `check_vault_health` command to diagnose the vault state (file, snapshot, client, and missing keys) from the app.

## Added

- Backend `check_vault_health` command and `checkVaultHealth()` frontend function to diagnose the Stronghold vault state, reporting whether the file exists, the snapshot loads, the `encrypt-keys` client is present, and which keys are missing. The check runs non-blocking at app startup. ([`8cee94c`](https://github.com/idmarinas/deployer-app/commit/8cee94c)) ([@idmarinas](https://github.com/idmarinas))

## Fixed

- Fixed the error where the backend decrypted the encrypted values incorrectly: `StrongholdVault::open` did not load the `encrypt-keys` client from the snapshot (`load_snapshot` does not populate it in memory), so `load_client` is now called explicitly. The attempt to create the client from Rust was also removed, leaving access strictly read-only, and clear error messages were added when the vault, client, or key does not exist. ([`8cee94c`](https://github.com/idmarinas/deployer-app/commit/8cee94c)) ([@idmarinas](https://github.com/idmarinas))
- Bumped the app version to 0.1.1 in `package.json` and `tauri.conf.json`. ([`0181f2a`](https://github.com/idmarinas/deployer-app/commit/0181f2a)) ([@idmarinas](https://github.com/idmarinas))
