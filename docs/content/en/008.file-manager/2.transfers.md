Select one or more entries from the tree icon and press the arrow in the middle. **Upload to server** copies each local entry into the current remote directory, keeping its name. **Download to computer** does the opposite with the chosen local folder. Checking a directory includes all its contents, unless the listing was cut off by the limits described in [Browsing files](./navigation).

::note
Descendants checked automatically when selecting a folder do not generate their own transfers: each block corresponds only to a top-level entry, so a file is never copied twice in the same batch.
::

## One connection per batch

All selected entries form **one batch** and share a single SSH/SFTP connection per server. The manager does not open a session per file, so a large selection does not trigger reconnections.

Batch items run **concurrently**, with a configurable maximum of **1 to 16** (2 by default). The limit is set in the **Transfers** tab, with the **Simultaneous transfers** field and the text **Up to {count} at a time**, and is saved as a preference; the change applies to the next batch you start, not to those already running. Items may finish in any order, but the queue is always shown newest to oldest and is not reordered by completion.

::note
Overwrite is enabled by default. The manager has no `chmod` or copy-mode fields: it uses automatic detection of the source type. The **chmod**, **Directory (recursive)** and **Auto (based on remote type)** / **File** / **Directory** controls belong to the console, not to this manager.
::

## Progress and cancellation

After the item starts and gets its slot, the backend enumerates the source recursively before copying; the remote pre-list is limited to 32 levels and skips broken links. Each file has its own bar and status, with byte-by-byte progress reading in 256 KB blocks; progress events have a minimum of 100 ms between them, except for the final event. The item summary accumulates the bytes of finished files when it completes successfully.

Per-file detail and the status of each item can be checked in the [transfer queue](./queue).

To cancel an item, use the **Cancel item** icon button in the queue or on the tree node. Cancellation is **individual** and reaches dependent items; a pending item is cancelled by its job identifier and becomes **Skipped**. Without an explicit key, the frontend cancels the job marked as active —for a batch, its first item—, while the backend cancels the last registered token. `cancel()` does not cancel the whole batch at once, but it does propagate cancellation to dependents.

::warning
Cancelling stops that item at the next 256 KB block and discards the partial file being written. Files already completed are kept; the connection continues serving the other items in the batch.
::

After a successful download, the top-level source entry —file or directory— is marked as **Downloaded** ([Browsing files](./navigation)). The mark no longer applies if the remote file's size or date changes.

::note
No remote management operations are offered to the user: you cannot create folders, rename, delete or edit content. During copying, directories are created, `chmod` is applied on upload and the partial file is deleted if cancelled.
::
