The manager organizes its content into two tabs: **Files**, with the independent **Local computer** and **Remote server** panels, and **Transfers**, with the queue. The local panel requires choosing a root folder; the remote one requires selecting an enabled host from the selector in its header. Local paths use the operating system separator; remote paths always use `/`.

## Remembered state

The active tab, the host, the local folder, the path for each host and, for each panel, the path, the selection, the loaded levels, the expanded folders and the result of the last read are stored in the local database, inside the snapshot of each listing; the selection is not a separate preference. When you reopen the manager, that snapshot is shown first and then revalidated in the background against the computer or the server. Entries that no longer exist are removed from the selection; if revalidation runs without preserving the state, the loaded levels are discarded too. Old `localStorage` preferences (tab, host, local folder and remote path) are migrated once the first time the manager is opened.

::note
On reopening, listings for deleted or disabled hosts are discarded. File selections are restored as long as the files are still present in the listed directory.
::

## Server base directory

The initial path of the remote panel comes from the server's **Base directory (file manager)** field. If it is empty, `/` is used. It is a preference separate from the remote console working directory: changing it does not affect commands or deployments. A remembered path of exactly `/` is ignored and replaced by the base directory. **Reset path** in the remote panel header goes back to that base directory, forgets the remembered path for that host and discards the snapshot of the current listing; it does not affect other saved paths for the host or other hosts.

## Level-by-level loading

Each panel lists **only the current level**. Expanding a directory requests that child level; the whole tree is not traversed at once. **Refresh** discards the levels already loaded and requests the current directory again.

The chosen local root folder also authorizes its subfolders, so you can walk through them level by level. If reading a directory fails, the error shows the affected path and the reason; SFTP session or invocation failures show a generic message.

The tree offers three distinct actions:

- The **icon** of an entry selects or deselects it for transfer. Checking a directory loads its descendants before completing the selection; symbolic links to folders are not traversed.
- The **folder name** expands or collapses a single level without checking anything: it lets you inspect the contents without selecting them.
- The **Open folder** button navigates to the directory and reloads the panel; it is not available for symbolic links.

Clicking the rest of the row does not change the selection.

::warning
Recursive selection stops after more than **5 levels**, **500 entries in a directory** or **5,000 nodes** in total (it cuts off at 501 and 5,001). The chosen directory and the levels reached are checked, and **Partial listing** and **The loading limit was reached; only the loaded levels were selected.** appear. To widen the scope, navigate to a subfolder.
::

::note
Both panels include hidden files and cap the listing at **1000 entries per directory** —in the local panel, in the frontend—. An entry is only marked as truncated when there are more than 1000: a directory with exactly 1000 entries shows no warning. If it appears, narrow the scope by changing directory instead of assuming you see everything.
::

## Tree order

In both panels, and also in the queue detail, folders come first and files after. Within each group the order is alphabetical according to the application language: accents and case are ignored and numbers are sorted naturally (`file2` before `file10`). The same criterion is applied to the levels saved when the manager is reopened.

In the remote panel, symbolic links show the target read —even if it is broken— and are placed according to the type of that target: those pointing to a folder go with folders and those pointing to a file go with files. In the local panel the target is not shown, although its type is also used for ordering. A broken link, an unresolvable target and the remaining special entries go last. The entry is still a symlink: only its position in the list changes.

::note
Icons distinguish by extension, including ZIP, TAR, `.env.docker`, `compose.yaml` and Docker Compose variants.
::

## Download marks

Remote files that have already been downloaded carry the **Downloaded** badge. The mark is stored in the local database and identified by server, remote path, size and modification date. Old `localStorage` marks are migrated once the first time the manager is opened.

::warning
If the remote file changes size or date, the mark no longer applies when it appears again in the listing. Marks for directories you have not listed again are kept.
::
