The **Migrations** settings tab lists the **migrations applied** to your database.

## What it shows

Each migration includes:

- **Version** — migration identifier.
- **Description** — what change it introduces.
- **Date** — when it was applied.
- **Execution time** — how long it took.
- **Status** — **successful** or **failed**.

## Relationship with the setup wizard

Migrations are applied automatically during the [initial setup](/app/setup):

- When **creating** a new database.
- When **selecting** an existing database (pending migrations are run).
- If migrations are missing on startup, the app redirects you to `/deployer/migrations` to run them before entering the dashboard.

## Management

This tab is **read-only**: migrations cannot be run or reverted here. Execution always happens through the application's setup flow.
