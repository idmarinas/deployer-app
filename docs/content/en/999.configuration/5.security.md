The **Security** settings tab lets you manage the **encryption keys** that protect sensitive data in the Stronghold vault.

## Encrypted fields

The fields that are encrypted (technical details of the mechanism are in [Stronghold vault](/app/vault)):

| Field | Table | Condition |
| --- | --- | --- |
| `password` | `deployer_hosts` | Always |
| `key_content` | `deployer_passkeys` | Always |
| `passphrase` | `deployer_passkeys` | Always |
| `value` | `deployer_variables` | Only when the variable is secret |

The tab shows the field identifier (`table.column`) and the **current version** of the key that encrypts it.

## Rotate key

Click **Rotate key** on a field to:

1. Generate a **new version** of the encryption key for that field.
2. **Re-encrypt** all existing values with the new version.
3. **Purge** old versions that are no longer used.

Rotation is the recommended measure if you suspect a key may have been compromised.

## Scan and re-encrypt all

The **Scan and re-encrypt all** button scans **all encrypted fields** and re-encrypts values that use an **old key version**, updating them to the current version. Useful after restoring a backup or under periodic rotation policies.

## Good practices

- Rotate keys if you think they may have been exposed.
- After a data restore, run **Scan and re-encrypt all** to homogenize versions.
- Keys reside in the **Stronghold vault**, whose password is stored in the **system keychain** (see [Security](/security)).
