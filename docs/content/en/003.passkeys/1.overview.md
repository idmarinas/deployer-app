**Access keys** (passkeys) are the **SSH private keys** you use to connect to your servers. You can use them as an authentication method on hosts ([Hosts](/hosts/overview)) or copy their public key to a server.

## Key types

:vars{n="project"} supports the three most common key types:

- **RSA (RSA-4096)** — the most universal; compatible with virtually every server.
- **Ed25519** — **recommended**: modern, fast and with shorter keys.
- **ECDSA (NIST P-256)** — based on elliptic curves, with limited use and sensitive to random generator failures.

## Access key fields

- **Name** — readable identifier (unique).
- **Description** — optional rich text.
- **Type** — RSA, Ed25519 or ECDSA. Derived from the content when saving.
- **Content** — the private key in PEM format, encrypted in the database.
- **Passphrase** — the key's passphrase (optional). If the key has one, it is required to use it.
- **Fingerprint** — the key fingerprint; derived automatically from the content when saving. On creation the field can be filled in, but it is overwritten with the derived value; on edit it is read-only.
- **Public key** — generated from the private key.

## Secure storage

The key **content** and **passphrase** are stored **encrypted** with AES-256-GCM using the Stronghold vault: the frontend performs the encryption and the backend only reads the vault. Both fields are marked with the encrypted type `encryptedText` and reads return a blank marker (`BLANK_VALUE`), so they appear **masked** in lists and detail views; only the **public key** is stored as plain text and shown as is. Vault settings are available in the app's Security section.

::note
The only key you can copy is the **public key**. When generating a pair, the **private key** is shown in plain text in the creation form; in all other views it appears masked. It is decrypted internally both to connect over SSH and to export the public key to a host.
::
