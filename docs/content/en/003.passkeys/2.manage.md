The **Access keys** module lets you manage all your SSH keys.

## List

The table shows **#**, **Name**, **Type** (uppercase), **Fingerprint** (truncated to 20 characters without the `SHA256:` prefix) and the **Enabled** state, with **Active**/**Inactive** badges. Each row can be expanded to see details and has quick actions: **View**, **Edit** and **Delete**; copying to a host is an icon-only button, with no text or tooltip.

:labels-version{version="0.3" is-new size="sm"} The **Active**, **Inactive** and **Deleted** tabs (with counters) organize the list; in **Deleted** you can **Restore**, **Delete permanently** and **Empty trash**, with **Undo** after deleting.

## Create a key

From **Add access key**, set the **name** (and the optional description), choose the **type** (RSA, Ed25519, ECDSA) and enter the **content** or use [Generate an access key](#generate-an-access-key). If the key has a **passphrase**, enter it: the creation form has a strength meter. On save, the **fingerprint** and **type** are calculated automatically from the content, although on creation you can fill in the fingerprint manually (it is overwritten).

## Generate an access key

The application can **generate an SSH key pair for you** with the *Generate access key* dialog, available **only when creating** an access key. This avoids relying on external tools (`ssh-keygen`) and you don't have to paste any content into the form.

1. In the creation form, click **Generate access key**.
2. Choose the **key type**: RSA, Ed25519 or ECDSA (Ed25519 by default).
3. Optionally, enter a **passphrase**. The interface shows a **strength meter** to help you choose a secure one.
4. Confirm with **Generate**.

The form is filled in automatically:

- **Private key** — the generated content.
- **Type** — the selected type.
- **Passphrase** — the passphrase, if you entered one.
- **Fingerprint** — the fingerprint derived from the key.

The **passphrase** is stored **encrypted** along with the key content (a field of type `encryptedText`) and is required to use the key against a host. The public key is recalculated on save.

## View :labels-version{version="0.2" is-new}

The detail view shows the fingerprint, the passphrase state (protected or not protected), the masked key content and the **public key**, with a button to copy it to the clipboard.

## Edit

The edit form is the same as the creation form, preloaded, but more restricted: **the key type, content, passphrase and fingerprint cannot be changed**, the strength meter is disabled and there is no generation button, so the pair cannot be regenerated.

## Delete :labels-version{version="0.3" is-new}

Deletion is **soft**: the key moves to the trash and can be restored or purged from the **Deleted** tab. If the key is assigned to one or more hosts, the dialog lists them and offers **Unlink and delete**: before continuing, the hosts are left with `key_id = NULL`. The `hosts.key_id` relationship uses `ON DELETE RESTRICT`, which prevents the **physical purge** of a key in use; the normal deletion is blocked or warned by the application itself in code.

## Enable / disable

The state is controlled by the toolbar toggle, which shows **Active**/**Inactive** (the table shows the **Enabled** badge). Disabled keys cannot be selected as an authentication method on a host.
