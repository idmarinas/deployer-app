**Commands** are **reusable** SSH tasks you can run against any server without typing them again.

## What a command stores

- **Name** — a readable identifier.
- **Key** — a unique slug identifier (lowercase letters, numbers and underscores between alphanumeric groups; no hyphens; 3 to 120 characters, or 3 to 64 when editing). It is **auto-generated** from the name, but you can adjust it on creation; in edit mode the field is read-only. Immutability is enforced by the UI, not the schema.
- **Description** — optional rich text.
- **Command** — the script or command to run over SSH (monospaced).
- **Output parser** — how the command output is interpreted ([Parsers](./parsers)).
- **Timeout** — maximum execution time (1-3600 seconds). The creation form and the database start at **30**; the schema and the runner fallback use **300**.
- **Input parameters** — definition of the values requested at run time and interpolated with `{{params.<key>}}`; the value is not saved ([Input parameters](./inputs)).

## What they are for

- **Automate** — repeated tasks (system status, logs, restarts, health checks...).
- **Test** — against a real host before using it ([Testing](./testing)).
- **Reuse** — the same definition on any enabled server.

## Internal commands

The app ships with **internal seed commands** that the UI itself uses for the [host views](/hosts/overview) ([Internal commands](./built-in)).

## Enabled

The **Enabled** toggle activates or deactivates the command; disabled commands cannot be run against a server, appear in the **Inactive** tab and keep the **Test** action, which fails with a disabled-command error ([Managing commands](./manage)).
