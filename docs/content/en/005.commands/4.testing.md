The **test dialog** lets you run a command against a real server and see its output before saving it or using it for real.

## How it works

1. Select a **host** (only enabled hosts are shown).
2. If the command declares [input parameters](./inputs), fill them in the **Input parameters** block: default values are resolved when the dialog opens and **any problem** (an empty required value, an unresolvable default or an invalid value) blocks **Run** with the **Check the parameters** notice. It is also disabled when no host is selected or global variables are missing.
3. The preview has two tabs: **Interpolated** (the default) shows the command with parameters and variables resolved and secrets masked as `••••••`; **Original** shows the unresolved template. The real run resolves secrets without masking. If there are interpolation or parameter errors, execution is blocked.
4. There is no incremental output during execution. On success the full output is shown along with **Exit code: 0**; if the command ends with a code > 0, the error message is shown with the output redacted and no code badge appears.

## Where it is available

- **Test button in the toolbar** of the creation form — runs the command you are defining, not yet saved.
- **Test button in the edit form** and the **Test** action in the table — run the saved definition, including its parameters. In the **Inactive** tab the test fails because the command is disabled.

## Differences by origin

- **Saved command** — uses the command's saved definition.
- **Ad-hoc command** — the text and parameters from the form, not yet saved.

::note
In edit mode, the preview uses the script and parameter definition from the form; the run uses the saved script, parser, timeout and definition, though with the values entered in the dialog. Save before testing if you changed the script or the parameter definition.
::

::note
The test uses the **credentials of the selected host** and verifies its **SSH fingerprint**, so it is a safe way to check that the command works against a specific host before automating it.
::
