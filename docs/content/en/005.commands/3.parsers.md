A command's **output parser** determines how its output is processed. It is set in the command's **Output parser** field, with a four-option selector and type-specific fields.

## Parser types

- **raw** — the output is not processed: it is shown as-is. Useful for commands whose output is meant for a person (logs, formatted status).
- **json** — the output is parsed as **JSON** and structured. Ideal for commands that return data (e.g. `uptime`, scripts with `--json`).
- **line-based** — the output is processed **line by line** into a `key → value` object (repeated keys are grouped into an array), with `string`, `number` or `boolean` transforms for listings and text tables.
- **regex** — the output is analyzed with a **regular expression** over the entire raw text, with `flags` and capture groups, to extract specific fields.

## Parser configuration

The parser is stored as an object with the configuration for the chosen type. The form offers a selector with four options and, depending on the type, structured fields: `match`/`key`/`transform` rules for `line-based`, and pattern, `flags` and groups for `regex`. There is no free-form JSON editor.

## Where it is used

The processed output is what lets the [internal commands](./built-in) present host data (system info, metrics and updates) in a structured form. The [command test dialog](./testing) only shows raw output and the exit code; it does not apply the parser.
