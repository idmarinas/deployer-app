:vars{n="project"} ships with a set of **internal (seed) commands** that the UI itself uses to populate the [host views](/hosts/overview).

## Included commands

| Command | Use in the app |
| --- | --- |
| `system_info` | Host [System information](/hosts/system-info) tab: OS, kernel, architecture, package manager, CPU cores, memory and disk (totals). |
| `system_metrics` | Host [Metrics](/hosts/metrics) tab: CPU, memory and disk usage, plus uptime. |
| `upgradable_packages` | Host [Updates](/hosts/updates) tab: list of upgradable packages with `apt`, `yum` or `dnf`. |
| `update_packages` | Host [Updates](/hosts/updates) tab: updates the selected packages with `sudo DEBIAN_FRONTEND=noninteractive apt-get install --only-upgrade -y`. |

## The update command

`update_packages` declares a single required text [input parameter](./inputs) (`packages`) with space-separated names (label **Packages**). The [Updates](/hosts/updates) view fills it with the selected packages before running it over SSH.

It requires passwordless `sudo` on the server, because the SSH session is non-interactive, and does not run `apt-get update`: refresh the index cache beforehand if it is stale. It only works with `apt-get` servers. In 0.4.0 the **Use sudo** option was removed: the script always uses `sudo`. It is an editable seed command; once edited, it is no longer overwritten by the seed.

## How they behave

- They are created automatically during the database's **initial setup** (seed).
- The parsers are `json` for system info and metrics, `regex` for upgradable packages and `raw` for `update_packages` ([Parsers](./parsers)); the latter does not structure the output.
- Their definition timeouts are 30 s for metrics and system info, 60 s for upgradable packages and 300 s for the update.
- They declare no [input parameters](./inputs): their output depends only on the host. The exception is `update_packages`, which receives the packages to update in the `packages` parameter.
- You do not need to touch them to use the app, but you can **test** them against a host to see exactly what they return.

## Associated wait times

Host views apply wait times when invoking these commands: **1 minute** for `system_info` and `system_metrics`, and **2 minutes** for `upgradable_packages`. There is no wait time in the backend.

::note
Although these commands appear in the **Commands** listing, they are part of the app's internal operation; you can edit them like any other command (since 0.4.0), but you cannot delete or purge them: being internal, the table and the CRUD prevent it. Modifying or disabling them can affect the host views.
::
