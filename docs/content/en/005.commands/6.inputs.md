An **input parameter** is a value the command requests before running and that is substituted into the script with the `{{params.<key>}}` expression.

Unlike [global variables](/variables/overview), a parameter is declared on the command itself and its value **is not saved**: it lives only for that run. The stored template does not change.

## Available types

- **text** — a free-form string. It also works for passing a space-separated list (see [Lists](#lists)).
- **number** — a finite number. An empty field is **not** converted to `0`: execution is blocked if the parameter is required and, if it is optional, it is interpolated as an empty string.
- **boolean** — a toggle. If left untouched it sends `false`, unless it has a `true` default value.
- **select** — one of the declared options. The value can be text or a number.

There is no `list` type or long-text type; use `text` with the list convention instead. There are no secret parameters either: secrets remain [global variables](/variables/overview).

## Defining parameters

In the command form, the **Input parameters** section (between the timeout and the script) lets you add, edit, reorder and remove parameters. Each one declares:

- **Key** — the slug used in the script: lowercase letters, numbers and underscores, starting with a letter.
- **Label** — the text shown in the run dialog.
- **Type** — one of the four above.
- **Required** — prevents running without a value.
- **Default value** — a literal or a global variable (see [Default values](#default-values)).
- **Help** — optional text next to the field.
- **Options** — only for `select`; at least one, with a unique, non-empty `value`.

A command supports up to **20** parameters. Saving rejects duplicate or malformed keys, empty labels, a `select` with no options or with empty or duplicate values, and a default value that does not match the type.

## Referencing in the script

The key is written as `{{params.key}}`:

```bash
if [ -d "{{params.remote_dir}}" ]; then
  ls -la "{{params.remote_dir}}"
fi
```

While typing, `{{` opens the available scopes (`global` and, if parameters are declared, `params`) and `{{params.` lists the declared keys. The linter flags references to keys that do not exist, but **does not prevent saving**; the [test dialog](./testing) does block execution until they are fixed.

## Default values

A default value can be a literal (`/var/www`, `22`, `true`) or an expression combining text with one or more `{{global.slug}}` references. It is resolved when the dialog opens and again in the runner for execution; before that there is a preview in the editor and validation on save.

Rules:

- Only root `global` variables are allowed, and they must exist, be **enabled** and **not be secret**. Otherwise the dialog shows the problem and does not allow running.
- There are no dependencies between parameters: a default value cannot reference `{{params.*}}`.
- A `boolean` only accepts a boolean literal.
- The resolved value is coerced to the type: a `number` must be numeric and a `select` must match one of its options.
- `Required` is evaluated after default values are applied, and `0` and `false` count as present values.
- If you clear a field that had a default value, an empty value is sent: the default is **not reapplied** during that run.

## Lists

A list is passed as **a single string with space-separated items**. The engine interpolates the text as-is and the remote shell applies *word splitting*.

```bash
# No quotes around the list expression in the command; quotes are used for the empty check.
if [ -n "{{params.packages}}" ]; then
  sudo DEBIAN_FRONTEND=noninteractive apt-get install --only-upgrade -y {{params.packages}}
fi
```

- **Do not quote** a list expression: with quotes, all items would arrive as a single argument.
- Do quote it when merely checking whether it is empty (`[ -n "…" ]`).
- The engine does not split or validate items; if the value comes from a dynamic selection, validate the items before joining them with spaces.

## Quoting and security

Substitution is **literal**, just like global variables. The command author decides the quoting based on the use: quote a single value (`"{{params.path}}"`) and do not quote a list.

::warning
The value is neither escaped nor sanitized. Everything the user types is inserted into the script; quoting correctly is the responsibility of whoever defines the command.
::

Parameter values are not stored in the database, are not reused between runs and are not shared across servers. For sensitive data, use secret global variables instead of parameters.

## Limits

- Maximum **20** parameters per command.
- Available types: `text`, `number`, `boolean` and `select`.
- No file inputs, no native lists and no secret parameters.
- Values are not persisted; each run starts with the declared default values.

To see how parameters combine with the rest of the template, check [Variable interpolation](/variables/interpolation) and [Parsers](./parsers).
