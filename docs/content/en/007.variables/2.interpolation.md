Use a variable by writing `{{global.slug}}`, where `slug` is the variable's slug. The **saved template is never changed**: substitution happens at execution time.

## Syntax

The `global` root is required and spaces are not allowed inside the braces:

```text
{{global.deploy_path}}     # valid
{{ global.deploy_path }}   # invalid (spaces)
{{global.deploy_path }}    # invalid (trailing space)
```

The slug uses lowercase letters, numbers and underscores; uppercase letters and hyphens are not supported.

To write the opening sequence literally, escape it with a backslash:

```text
\{{global.deploy_path}}   # sent as {{global.deploy_path}}
```

::note
The parser recognizes other roots, but the application only supplies `global`. A reference such as `{{vars.x}}` produces a "scope not available" error and **blocks execution**; it is not left as literal text. In contrast, unrelated formats such as `{{.Names}}`, `{{end}}`, `{NAME}` or `${NAME}` are left untouched.
::

## Where it applies

- In the **command** and the **working directory** of saved commands.
- In the **manual console**, which interpolates references but offers no linter, autocomplete or preview.

The command form linter warns about missing or disabled references, but **does not prevent saving**. The test dialog, on the other hand, **blocks execution** while there are errors.

## Autocomplete and highlighting

In the editor, `{{` opens the list of scopes — currently only `global` — and variables appear as you type a letter. Filtering works by both slug and name:

```text
{{             # available scopes (global)
{{g            # global and its variables
{{global.      # all global variables
{{global.de    # global.deploy_path
{{de           # global.deploy_path (matches by slug)
```

Each option shows the **name** and, below it, the expression together with a preview of its value (`global.deploy_path [/var/www]`). Long values are truncated with `…`; secrets show `••••••` and the option has a lock icon. Accepting a secret only inserts `{{global.slug}}`, **never its value**.

References are highlighted in the primary color and secrets in amber. This is informational highlighting: a secret variable is **not** an error or a warning.

## Test dialog preview

When the command contains references, the **Test command** dialog shows two tabs:

- **Interpolated** (default): the command as it will be sent to the host, with variables resolved and secrets masked as `••••••`.
- **Original**: the saved template, unresolved.

In both views expressions are highlighted, and a note below the preview reminds you that these variables are only resolved when the command runs. If the template has errors, the interpolated view cannot be computed and execution is blocked.

## Resolution

- Only **enabled** variables are resolved.
- A missing or disabled reference **blocks execution**.
- Secret variables are decrypted only at execution time; in forms, previews and logs they appear masked (`••••••`). Error messages are redacted too.
- There is no recursion: a variable's value is not interpolated again.
