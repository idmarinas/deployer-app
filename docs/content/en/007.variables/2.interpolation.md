Use a variable by writing `{{global.slug}}`, where `slug` is the variable's slug. The **saved template is never changed**: substitution happens at execution time.

## Syntax

References support `global` for variables and `params` for parameters declared in the command; spaces are not allowed inside the braces:

```text
{{global.deploy_path}}     # valid
{{params.remote_dir}}      # valid in a command with that parameter
{{ global.deploy_path }}   # invalid (spaces)
{{global.deploy_path }}    # invalid (trailing space)
```

::note
`params` is available since 0.4.0; `global` since 0.3.0.
::

Declared slugs use lowercase letters, numbers and underscores. If you write uppercase letters in the reference, the parser interprets it and fails as an unknown variable; hyphens are left as literal text.

To write the opening sequence literally, escape it with a backslash:

```text
\{{global.deploy_path}}   # sent as {{global.deploy_path}}
```

::note
The application only supplies `global` and, in commands with declared input parameters, `params`. A reference such as `{{vars.x}}` produces a "scope not available" error and **blocks execution**; it is not left as literal text. In contrast, unrelated formats such as `{{.Names}}`, `{{end}}`, `{NAME}` or `${NAME}` are left untouched.
::

## Where it applies

- In the **command** of saved commands.
- In the **command** and the **working directory** of the manual console, which interpolates references but offers no linter, autocomplete or preview.

The command form linter warns about missing or disabled references, but **does not prevent saving**. The test dialog, on the other hand, **blocks execution** while there are errors.

## Autocomplete and highlighting

In the editor, `{{` opens the list of scopes (`global` and, if the command declares parameters with a key, `params`) and variables appear as you type a letter. Filtering works by both slug and name:

```text
{{             # available scopes (global, params)
{{g            # global and its variables
{{global.      # all global variables
{{global.de    # global.deploy_path
{{de           # global.deploy_path (matches by slug)
{{params.      # declared parameter keys
```

Each option shows the **name** and, below it, the expression together with a preview of its value (`global.deploy_path [/var/www]`). Long values are truncated with `…`; secrets show `••••••` and the option has a lock icon. Accepting a secret only inserts `{{global.slug}}`, **never its value**. Parameters show their label and the declared type.

References are highlighted in the primary color and secrets in amber. Highlighting is informational; the linter does emit a warning for secrets, shown in the test dialog, but it does not prevent saving.

## Test dialog preview

When there are resolvable references and the template has no errors, the **Test command** dialog shows two tabs:

- **Interpolated** (default): a preview with variables resolved and secrets masked as `••••••`, using the provisional parameter values. The actual run resolves secrets without masking them.
- **Original**: the command template, unresolved.

Expressions are highlighted in both views. The note below the preview only appears when there are secrets and refers to them: they are resolved when the command runs. If the template has errors, the interpolated view cannot be computed, the tabs are hidden and execution is blocked.

## Resolution

- Only **enabled** variables are resolved.
- A missing or disabled reference **blocks execution**.
- Secret variables are decrypted only at execution time; in forms, previews and logs they appear masked (`••••••`). Error messages are redacted too.
- There is no recursion: a variable's value is not interpolated again.
