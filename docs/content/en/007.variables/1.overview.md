**Global variables** are values with a readable name and a unique **slug** that can be reused in commands, in the console working directory and as defaults for input parameters. See [Interpolation](./interpolation) for how to use them.

## What a variable stores

- **Slug** — the stable key used in expressions. It is **auto-generated** from the name and **locked** when editing; when creating the variable you can unlock it and customize it.
- **Name and slug** — uniqueness is checked even when the row is in the trash.
- **Enabled** — a disabled variable is not resolved, but the linter distinguishes it from a missing one.
- **Secret** — the value is encrypted and cannot be made public again in that row.

The other form fields —rich text description and value— do not change interpolation behavior.

## Value and secrets

The value is required when creating the variable if it is **enabled** or marked as **secret**; a disabled, non-secret variable can remain a draft with an empty value.

Secret variables are stored **encrypted** with the vault keys (`encryptedText(...)` on the `value` column). Normal reads never return the real value: the expanded list row shows only a masked marker. The value is decrypted only when a flow needs it.

::warning
A variable marked as secret **cannot be made public again**. The secret option is locked when editing, and the data layer forces `is_secret = true` if the record was already secret.
::
